# Implementation plan: Rename the page heading to "My tasks"

> Provenance is added by the coordinator. Implements the approved specification revision named in the provenance.

## Approach
Change the literal text of the single `<h1>` in `src/App.tsx` from "Task list" to "My tasks".
Nothing else in the component changes: same element, level, position and (absent) classes.
Update the existing e2e assertion that names the heading, and add component tests in
`src/App.test.tsx` that pin the new heading (AC1), the absence of the old heading (AC2), and the
unchanged rest of the page (AC3). No new dependencies, no ADR needed.

## Affected files
| Path | Change |
|---|---|
| src/App.tsx | modify: line 46, `<h1>Task list</h1>` → `<h1>My tasks</h1>` |
| src/App.test.tsx | modify: add three component tests (see mapping) |
| e2e/app.spec.ts | modify: line 5, heading assertion updated to "My tasks" (exact, level 1) plus a negative check for "Task list" |

Explicitly not touched: `index.html` (`<title>Task list</title>` stays, per spec exclusion and A3),
`README.md`, `CLAUDE.md`, `docs/**`, styling.

## Interfaces and data
None. `App` props, exported functions, types, storage keys and formats are unchanged.

## Implementation steps
1. `src/App.tsx:46`: replace the heading text with `My tasks` (capital "M", lowercase "t", no
   punctuation, per spec A1).
2. `src/App.test.tsx`: add inside the existing `describe("App")` block:
   - `it("shows a single level-1 heading reading exactly 'My tasks' (SDLC-12 AC1)")`:
     `screen.getAllByRole("heading", { level: 1 })` has length 1 and
     `screen.getByRole("heading", { level: 1, name: "My tasks" })` is in the document.
   - `it("no longer shows 'Task list' as a page heading (SDLC-12 AC2)")`:
     `screen.queryByRole("heading", { name: /task list/i })` is null.
   - `it("keeps the welcome block, filters, count line and task list unchanged (SDLC-12 AC3)")`:
     region "Welcome" has text "HELLO WORLD"; labelled "Status" select and "Starred only"
     checkbox (unticked) are present; text `Showing ${TASKS.length} of ${TASKS.length} tasks · 0 starred`
     is present; list "Tasks" has `TASKS.length` items.
   Existing tests are kept as they are; they continue to cover filter behaviour, star toggles and
   persistence for AC3.
3. `e2e/app.spec.ts:5`: change to
   `await expect(page.getByRole("heading", { level: 1, name: "My tasks", exact: true })).toBeVisible();`
   and add
   `await expect(page.getByRole("heading", { name: "Task list" })).toHaveCount(0);`.
   The rest of the journey is unchanged and keeps covering AC3 in a real browser.
4. Run `npm run lint`, `npm run typecheck`, `npm run test:unit`, `npm run build`,
   `npm run test:e2e` (with `PORT`/`E2E_PORT` set by the coordinator).
