# Implementation plan: Search by task name

> Provenance is added by the coordinator. Implements the approved specification revision named in the provenance.

## Approach
Extend `TaskQuery` in `src/domain/filter.ts` with a required `search: string` field and apply it
inside `filterTasks` alongside the existing status and starred predicates (logical AND). This is
what `docs/architecture.md` asks for. Matching goes in a small exported pure function,
`matchesSearch(title, search)`. It trims leading and trailing whitespace from the search text,
lowercases both sides with `String.prototype.toLowerCase()` and uses `String.prototype.includes`.
Because it uses `includes`, the text is always treated as a plain substring and never as a
pattern (spec NFR Security, A3, A4). An empty or whitespace-only search matches every title (A2).

`App` holds the raw `search` string in React state, so the input shows exactly what the user typed.
It passes that string to `filterTasks` inside the existing `useMemo`, so the list, the
"Showing X of Y tasks" count and the empty state all come from the same `visible` array
(AC4, AC5). Sorting runs after filtering, so result order does not change (A5). The search
is not persisted anywhere (A6).

The control is a `<label htmlFor="search-filter">Search</label>` plus
`<input id="search-filter" type="search">`. It is the last control in the existing
`<div className="controls">` row, after "Starred only", so the Tab order of the existing controls
stays the same (A7). `type="search"` exposes the `searchbox` role, and the native clear button
fires a normal change event with `""`, which meets AC6 (A8). There is no `autoFocus` (NFR
Accessibility) and no debounce (NFR Performance).

No new dependencies, storage formats or migrations. No ADR is needed.

## Interfaces and data
- `TaskQuery` (exported interface, `src/domain/filter.ts`) gains `readonly search: string;`.
  The field is required, matching the existing fields, so every caller states its search
  explicitly. The callers today are `App.tsx` and `filter.test.ts`, and both are updated in this
  change.
- New export: `matchesSearch(title: string, search: string): boolean`. It is pure. It returns
  `true` when `search.trim()` is empty. Otherwise it returns
  `title.toLowerCase().includes(search.trim().toLowerCase())`.
- `filterTasks` signature is unchanged. Its predicate gains `&& matchesSearch(task.title, query.search)`.
- `sortTasks`, `Task`, `StatusFilter`, the storage (`starred.ts`) and the `TaskList` props are unchanged.
- No storage format, schema or URL changes.

## Implementation steps
1. **Domain** (`src/domain/filter.ts`):
   - Add `readonly search: string;` to `TaskQuery`.
   - Add `export function matchesSearch(title: string, search: string): boolean`, with a one-line
     doc comment ("Case-insensitive title substring match; surrounding whitespace in the search is
     ignored."). Trim the search once, return `true` if the result is empty, and otherwise compare
     the lowercased strings with `includes`.
   - In `filterTasks`, AND `matchesSearch(task.title, query.search)` onto the existing predicate.
2. **Domain tests** (`src/domain/filter.test.ts`):
   - Add `search: ""` to each existing `filterTasks` query literal so it typechecks. No other
     change to existing tests.
   - Add `describe("matchesSearch", ...)` with tests for:
     - an empty search;
     - a whitespace-only search;
     - case-insensitive matching;
     - surrounding spaces being trimmed;
     - internal spaces being matched literally;
     - no match;
     - regular-expression metacharacters being treated literally (for example, `"("` does not
       throw and matches nothing in the fixtures).
   - Add `filterTasks` search tests that use the fixtures. See the mapping below for the exact
     expected IDs.
3. **UI** (`src/App.tsx`):
   - Add `const [search, setSearch] = useState("");`.
   - Pass `search` into the `filterTasks` query and add it to the `useMemo` dependency array.
   - Inside `<div className="controls">`, after the Starred only checkbox, add
     `<label htmlFor="search-filter">Search</label>` and
     `<input id="search-filter" type="search" value={search} onChange={(e) => setSearch(e.target.value)} />`.
   - Do not change the count line, its `aria-live` wrapper or `TaskList`.
4. **Component tests** (`src/App.test.tsx`): add the tests named in the mapping. Query by role or
   label (`getByRole("searchbox", { name: "Search" })`). Type with `userEvent` and clear with
   `user.clear`.
5. **E2E** (`e2e/app.spec.ts`): add a separate `test("searches tasks by title combined with other filters", ...)`.
   Playwright gives each test a fresh context, so starred state from the existing test does not
   leak into it.
6. Run `npm run lint`, `npm run typecheck`, `npm run test:unit`, `npm run build` and
   `npm run test:e2e`.

Fixture facts the tests rely on (titles at `be71a8c`). A case-insensitive `"re"` matches **six**
tasks:

| ID | Title |
|---|---|
| t-002 | Review quarterly roadmap |
| t-003 | Book team **re**trospective |
| t-006 | P**re**pare demo environment |
| t-007 | Write **re**lease notes |
| t-009 | Order **re**placement keyboards |

## Coordination
`related_work` is empty for this run. No other in-flight ticket is reported as touching
`src/domain/filter.ts`, `src/App.tsx` or their tests. This change is behind SDLC-7 and SDLC-10,
which are already merged into `main` at `be71a8c`. Making `TaskQuery.search` required is a source
change to a shared type. Any later ticket that builds a `TaskQuery` literal will have to supply
`search`, and the typecheck will flag it.

## Risks
| Risk | Mitigation |
|---|---|
| Making `TaskQuery.search` required breaks other callers | The only callers are `App.tsx` and `filter.test.ts`, and both are updated in this change. `npm run typecheck` confirms there are no others. |
| The "re" example in the spec lists four titles, but the fixtures give six | The tests assert the actual six. The spec says "such as", so this matches the spec. |
| The native clear button on `type="search"` behaves differently across browsers | It fires a normal input or change event with `""`, which goes through the same `onChange`. AC6 is tested by clearing the value in both the component and e2e tests, so it does not depend on the button. |
| Ambiguous queries in tests: `getByText("Showing …")` or `getByLabelText("Search")` could match more than one element | Only one "Search" label exists. The count assertions use `exact: false` on the unique count paragraph, as the existing tests do. |
| Lowercasing non-ASCII text (for example Turkish dotted I) | Out of scope by A3. The fixtures are ASCII. |

## Rollback implications
This change is client-side only. It adds no persisted state, storage keys, schema or migration,
and the search text is held in memory only. To roll back, revert the feature commit. That restores
`TaskQuery` to its previous shape. No data cleanup is needed, and users' starred IDs in
`localStorage` are not affected.
