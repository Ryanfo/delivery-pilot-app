# Release proposal

> Provenance (ticket, revision, accepted candidate SHA) is added by the coordinator.

## Release notes
**New: search tasks by name.** The filter controls above the task list now include a search box.
It shows the word "Search" inside the field until you type. As you type, the list shows only tasks
whose title contains your text.

- Matching ignores upper and lower case, and spaces at the start or end of your search are ignored.
  Spaces inside your search count, so "release notes" finds "Write release notes".
- Search works together with the Status and Starred only filters. A task is shown only if it
  matches all of them.
- The "Showing X of Y tasks" line counts only the tasks left visible. If nothing matches, you see
  "No tasks match the current filter."
- Clear the box to see the tasks again.
- Search looks at task titles only, not descriptions. It is not remembered between visits and
  resets when the page reloads. Matched text is not highlighted.

Accessibility note: the search box has no visible label next to it. It shows "Search" as
placeholder text and has the accessible name "Search" for assistive technology. This is an
exception to the visible-label coding standard, approved in specification v002, and it applies to
this input only.

## Rollback
The change is client-side only. It adds no persisted state, storage keys, schema or migration, and
the search text is held only in memory.

1. On GitHub, use **Revert** on the merged SDLC-13 pull request, or locally run
   `git revert -m 1 <merge-commit>` (use `git revert <commit>` for a squash merge) on a new branch
   from `main`, then open a PR.
2. Let required CI pass on the revert PR, get a human review, and merge it. Typecheck confirms that
   no other caller still depends on `TaskQuery.search`. If a later merged ticket already supplies
   `search`, update or revert that ticket too.
3. Rebuild and redeploy `main` to the local-pilot environment (`npm ci`, `npm run build`,
   `PORT=<free port> npm run preview`).
4. Confirm the rollback: the controls row shows only Status and Starred only, "Showing 12 of 12
   tasks" is shown, the Status and Starred only filters still work, and stars set before the
   rollback are still shown.
5. No data cleanup is needed, because users' starred IDs in `localStorage` are not touched by this
   change. Record the rollback in Jira on SDLC-13.
