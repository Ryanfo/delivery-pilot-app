# Release proposal

> Provenance (ticket, revision, accepted candidate SHA) is added by the coordinator.

Release proposal v001 for SDLC-18 "Update status of items". Implements specification v003 and
plan v001. The independent review and verification both found every criterion (AC1–AC8) met,
with no deviations and no defects.

## Release notes
**You can now change a task's status from the task list.**

- Each task now has a **Status** control, after its star button, offering "To do",
  "In progress" and "Done". Pick a new value and the task's status updates straight away.
- The status filter and the "Showing X of Y tasks" count use the new status at once. If a
  status filter is active and you move a task to a different status, the task leaves the
  list immediately; select its new status in the filter to see it again.
- You can use the control with the keyboard alone: Tab to it and change the value. Each
  control is announced with its task's name, for example "Status for Draft onboarding
  checklist".
- Your changes are saved in this browser and stay after a page reload, the same way stars
  do. They are not shared with other browsers or devices.
- Starring, "Starred only", search and the status filter work as before, and your saved
  stars are unaffected.

Not included: editing other task fields, bulk status changes, undo/history, or a "reset to
original status" action. To undo a change, set the task back to its earlier status.

## Smoke checks
Run against the merged commit, profile `local-pilot`. Use the port the coordinator reserved
for the run; never assume the default.

1. From a clean checkout of the release commit run `npm ci`, then `npm run build`; it must finish without errors.
2. Start the app with `PORT=<reserved port> npm run preview` (or `npm run dev`) and open `http://127.0.0.1:<reserved port>/` in a fresh browser profile or private window, so that no earlier `localStorage` is present.
3. The page loads and shows "Showing 12 of 12 tasks". Every task has a "Status" control after its star button; "Draft onboarding checklist" shows "To do" in both its meta line and its control, which offers exactly "To do", "In progress" and "Done".
4. Set the status filter to "To do": the list shows "Showing 6 of 12 tasks".
5. Change "Draft onboarding checklist" to "Done" with its Status control: the task leaves the list at once and the line reads "Showing 5 of 12 tasks" (starred count unchanged).
6. Set the status filter to "Done": "Draft onboarding checklist" is listed with "Done" in its meta line and control, and the line reads "Showing 4 of 12 tasks".
7. Set the filter back to "All": all 12 tasks show, "Draft onboarding checklist" is in the same position as before, and every other task keeps its original status.
8. Keyboard check: Tab to a task's star button, press Tab once more to reach its Status control, confirm a visible 2px accent focus ring, then change the value with the keyboard (arrow keys or type-ahead); the task's displayed status updates.
9. Reload the page: "Draft onboarding checklist" (and any task changed in step 8) still shows the status you set, in the meta line, the control, the status filter results and the count; unchanged tasks show their original status.
10. Star a task, reload, and confirm the star survives alongside the changed statuses; "Starred only" and search still filter as before.
11. Resilience: in DevTools set `localStorage["task-list:status:v1"]` to `not json` and reload; the page renders with original statuses and no error is shown. Then set it to `{"t-999":"done","t-002":"blocked"}` and reload; the page renders and those entries are ignored ("Review quarterly roadmap" still shows "In progress").
12. Optionally run `npm run test:unit` and `E2E_PORT=<reserved port> npm run test:e2e` on the release commit; both pass.

## Rollback
1. Revert the release on GitHub: open a PR that reverts the merge commit (`git revert -m 1 <merge commit>` on a branch from `main`), get it reviewed and merge it. Do not force-push `main`.
2. Rebuild and redeploy the reverted `main` for the `local-pilot` profile (`npm ci && npm run build`, then restart `npm run preview`/`npm run dev` on the reserved port).
3. Check that the page loads with "Showing 12 of 12 tasks", has no per-task Status controls, and that stars still work.
4. No data migration is needed. The leftover `task-list:status:v1` browser entry is ignored by the reverted code, so tasks show their fixture statuses again; stars (`task-list:starred:v1`) are unaffected. Users may remove the entry from DevTools if they wish, but it is harmless.
5. If the change is later re-released, statuses saved in that entry will reappear; clear it before re-release only if that is not wanted.
6. Note the rollback and the revert PR on SDLC-18 so the team knows the feature is no longer live.
