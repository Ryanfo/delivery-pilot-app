# ADR-001: Scroll-triggered card reveal via a feature-detected IntersectionObserver hook, with reduced motion handled in CSS

> Provenance is added by the coordinator. Status: Proposed (humans accept ADRs).

## Context
AC8 requires each task card to visually reveal itself as it scrolls into view, without removing
any card from the DOM/accessibility tree, and without new dependencies (`docs/guardrails.md`).
It must also respect `prefers-reduced-motion: reduce`. The codebase has no existing hooks,
observers or per-item animation, and `TaskList` currently renders all task `<li>` elements from
one `.map()` call with no per-item component boundary.

React's Rules of Hooks require a hook (needed per card, for its own `IntersectionObserver`) to
be called from a stable component instance, not from inside a `.map()` callback in a shared
component's render body — the number of calls there varies with the filtered task count between
renders, which hooks do not allow.

## Decision
- Extract a small, local (not exported) `TaskCard` component inside
  `src/components/TaskList.tsx`, rendering the same `<li><h2><p><p><button>` structure as today,
  so each card is its own component instance.
- Add a new hook, `useRevealOnScroll`, in `src/components/useRevealOnScroll.ts`: it attaches an
  `IntersectionObserver` to a ref'd element, sets `isVisible` to `true` and disconnects on first
  intersection (reveal-once). If `IntersectionObserver` is not defined in the current
  environment (older browser, or jsdom under Vitest), it sets `isVisible` to `true` immediately
  instead of throwing or leaving the card hidden.
- Handle `prefers-reduced-motion: reduce` entirely in CSS, with a media query that forces the
  card's final (visible, non-transformed) state and removes the transition, independent of the
  `isVisible` class. No `window.matchMedia` call is added to application code.

## Alternatives considered
- **A scroll/animation library.** Rejected: the specification and `docs/guardrails.md` both
  require no new runtime dependency; native `IntersectionObserver` is sufficient and already
  the example given in the specification.
- **Reading `prefers-reduced-motion` in JavaScript** (`window.matchMedia`) and conditionally
  skipping the observer. Rejected: jsdom does not implement `matchMedia`, so every component
  test touching `TaskList` would need a mock; a CSS media query achieves the same outcome with
  no test-environment dependency and no risk of the JS and CSS states disagreeing.
  Browser support for CSS's `prefers-reduced-motion` and `IntersectionObserver` match for the
  browsers this app targets.
  (If reduced motion ever needs to change rendered content rather than only CSS, this would
  need revisiting.)
- **One shared `IntersectionObserver` observing all cards**, instead of one per card via the
  hook. Rejected as unnecessary for a fixed 12-item list; one observer per card keeps the hook
  simple and self-contained, and the cost is negligible at this scale. Revisit if the list
  stops being a small, fixed, synthetic dataset.
- **Mocking `IntersectionObserver` in `src/test-setup.ts`** instead of feature-detecting in the
  hook. Rejected: it would make every component test implicitly depend on a global mock that
  isn't obvious from the test file itself, and it does nothing for real-world browsers that lack
  the API. Feature-detection in the hook handles both cases with one code path and keeps
  `src/test-setup.ts` (shared test infrastructure) untouched.

## Consequences
- Component tests for `TaskList`/`App` need no browser-API mocking: cards render immediately
  visible in jsdom, which also happens to be the correct accessible fallback for a browser
  without `IntersectionObserver`.
- The reveal animation and the reduced-motion override can only be verified against real
  rendered CSS, so AC8's test coverage lives in Playwright (`e2e/styling.spec.ts`), not in the
  Vitest/Testing Library suite.
- `TaskList.tsx` gains one more exported-from-module-but-not-exported-from-package symbol
  (`TaskCard`); `TaskList`'s own public props and the rendered DOM are unchanged, so no other
  file needs to change because of this split.
