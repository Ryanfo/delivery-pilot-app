# Implementation plan: Styling

> Provenance is added by the coordinator. Implements the approved specification revision named in the provenance.

## Approach
Add one plain global stylesheet, `src/styles.css`, and import it once from `src/main.tsx`
(`import "./styles.css";`). Vite already bundles imported CSS with no new dependency, so there
are no extra runtime requests (NFR Performance and Security). Importing it from `main.tsx` and
not from `App.tsx` keeps the Vitest/jsdom component tests exactly as they are: they render
`<App />` directly and never load the stylesheet.

The editorial look (spec, "Interpretation of 'editorial'" and A1) is set with CSS custom
properties declared on `:root`. They give a paper-and-ink palette with one deep-red accent,
three system font stacks (serif display, serif body, sans-serif kicker), a single 48rem reading
column and thin horizontal rules instead of cards. All font sizes use `rem`/`em`.

Markup changes are limited to adding `className` attributes, so the styles do not depend on
fragile structural selectors such as `p:nth-of-type(2)`. No element is added, removed,
re-ordered or re-parented, and no text, role, `aria-*` or `data-testid` changes (AC13). The
controls stay direct siblings inside `.controls`, because `src/App.test.tsx` asserts that
Search, Status and Starred only share one parent. The responsive controls row therefore uses
`display: flex; flex-wrap: wrap` on the existing `div.controls` and needs no wrapper elements.

The visual criteria AC1 to AC12 are checked in a real browser in a new Playwright spec,
`e2e/styling.spec.ts`. It uses computed-style assertions. A small pure helper computes WCAG
contrast ratios. Full-page screenshots at 1280px and 320px are attached to the test report for
human review, without pixel-baseline comparisons, because system fonts differ between macOS and
the CI Linux runner.

No architectural decision needs an ADR. Plain CSS through Vite is the mechanism the
specification proposes, and it adds no dependency.

## Interfaces and data
- No exported TypeScript function, type, prop, storage format or schema changes. `App` and
  `TaskList` props and their DOM structure stay the same. Only `className` attributes are added.
- New CSS class names (a styling contract only): `masthead`, `standfirst`, `results`, `task`,
  `task-title`, `task-description`, `task-meta`, `star-button`, `empty-state`. The existing
  `controls` and `task-list` classes are now styled.
- New CSS custom properties on `:root` (design tokens). Values are proposed and the contrast
  ratios are computed against `--paper`:

  | Token | Value | Use | Contrast vs paper |
  |---|---|---|---|
  | `--paper` | `#f7f4ee` | page background (AC1) | n/a |
  | `--ink` | `#1c1b19` | body text, headings (AC1) | ≈ 15.7:1 |
  | `--muted` | `#5c5750` | kicker, results, placeholder, empty state (AC4, AC10, AC12) | ≈ 6.4:1 |
  | `--accent` | `#a3222b` | starred fill, focus ring, checkbox `accent-color` (AC8, AC9) | ≈ 6.7:1 |
  | `--rule` | `#cfc8bb` (masthead rule uses `--ink`) | task separators (AC6) | decorative |
  | `--font-display` | `"Iowan Old Style", "Palatino Linotype", Palatino, "Book Antiqua", Georgia, serif` | masthead, task titles (AC2, AC3) | n/a |
  | `--font-body` | `Charter, "Bitstream Charter", "Sitka Text", Cambria, Georgia, serif` | body, descriptions, controls, empty state (AC3, AC7, AC12) | n/a |
  | `--font-kicker` | `system-ui, -apple-system, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif` | labels, metadata, standfirst, star button (AC4) | n/a |

  The starred button uses `--paper` text on an `--accent` fill (≈ 6.7:1). The implementer may
  adjust the exact values if the AC10 test shows a different result, as long as every ratio in
  AC9 and AC10 still passes.
- New test helper module `e2e/support/contrast.ts` exports `parseRgb(css: string): {r,g,b,a}`
  and `contrastRatio(fg: string, bg: string): number`. It is pure and has no Playwright
  dependency.

## Implementation steps
1. **Load the stylesheet.** Create `src/styles.css`, which starts with the `:root` tokens
   above. Add `import "./styles.css";` to `src/main.tsx`. Add `src/vite-env.d.ts` containing
   `/// <reference types="vite/client" />`. Run `npm run typecheck` and `npm run build` to
   confirm the import compiles and the CSS is emitted in `dist/assets`.
2. **Base styles** (AC1, AC3, NFR):
   - `*, *::before, *::after { box-sizing: border-box; }`
   - `html { background: var(--paper); }`
   - `body { margin: 0; background: var(--paper); color: var(--ink); font-family: var(--font-body); font-size: 1rem; line-height: 1.6; }`.
     Do not change the root font size, so 1rem stays at the browser default (16px).
3. **Reading column** (AC5, AC11): `main { max-width: 48rem; margin: 0 auto; padding: 2.5rem 1.5rem 4rem; }`,
   with `padding-inline: 1rem` below 480px. Every page section sits inside `main`, so they all
   share the column.
4. **Masthead and standfirst** (AC2, A4):
   - `.masthead`: `font-family: var(--font-display)`, `font-size: clamp(2.5rem, 2rem + 4vw, 4rem)`,
     `font-weight: 700`, `line-height: 1.05`, `letter-spacing: -0.01em`, centred,
     `margin: 0 0 0.75rem`, `padding-bottom: 0.75rem`,
     `border-bottom: 3px double var(--ink)`.
   - `.standfirst`: kicker font, `0.8125rem`, `letter-spacing: 0.2em`, centred, `--muted`
     colour, with margin under it. The text stays "HELLO WORLD".
5. **Controls bar** (AC4, AC7):
   - `.controls { display: flex; flex-wrap: wrap; align-items: center; gap: 0.75rem 1rem; padding: 1rem 0; border-top: 1px solid var(--rule); border-bottom: 1px solid var(--rule); }`
   - `.controls label`: kicker style (`var(--font-kicker)`, `0.75rem`, `text-transform: uppercase`,
     `letter-spacing: 0.12em`, `color: var(--muted)`). Give `margin-right` to the label before
     each control so each label sits next to its control.
   - `select, input[type="search"] { font: inherit; color: var(--ink); background: #fffdf8; border: 1px solid var(--muted); border-radius: 0; padding: 0.375rem 0.5rem; }`.
     The off-white field background keeps placeholder contrast above 4.5:1.
   - `input[type="search"] { flex: 1 1 12rem; min-width: 0; }` and
     `input[type="search"]::placeholder { color: var(--muted); opacity: 1; }`
   - `input[type="checkbox"] { accent-color: var(--accent); width: 1.125rem; height: 1.125rem; }`
6. **Results line** (AC10): `.results`: kicker font, `0.875rem`, `--muted`, `margin: 1rem 0 0.5rem`.
   It is not uppercased, so it reads as a sentence.
7. **Task list** (AC3, AC4, AC6):
   - `.task-list { list-style: none; margin: 0; padding: 0; }`
   - `.task { padding: 1.5rem 0; background: transparent; box-shadow: none; border-radius: 0; }`
     and `.task + .task { border-top: 1px solid var(--rule); }`
   - `.task-title { font-family: var(--font-display); font-size: 1.5rem; line-height: 1.2; margin: 0 0 0.375rem; }`
   - `.task-description { font-size: 1rem; line-height: 1.6; margin: 0 0 0.5rem; }`
   - `.task-meta`: kicker style (`0.75rem`, uppercase, `letter-spacing: 0.12em`, `--muted`, `margin: 0 0 0.75rem`).
8. **Star button** (AC8):
   - `.star-button { font-family: var(--font-kicker); font-size: 0.8125rem; letter-spacing: 0.04em; color: var(--accent); background: transparent; border: 1px solid var(--accent); border-radius: 0; padding: 0.3rem 0.75rem; cursor: pointer; transition: background-color 120ms, color 120ms; }`
   - `.star-button[aria-pressed="true"] { background: var(--accent); color: var(--paper); }`.
     It keys off the existing `aria-pressed`, so no state class is added. The "★ Starred" and
     "☆ Star" text stay as they are, so the state is never shown by colour alone.
   - `.star-button:hover`: an underline or a slight tint that keeps contrast.
9. **Focus** (AC9): `select:focus-visible, input:focus-visible, button:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px; }`.
   Do not use `outline: none` anywhere.
10. **Empty state** (AC12): `.empty-state { font-family: var(--font-body); font-style: italic; color: var(--muted); padding: 2rem 0; text-align: center; border-bottom: 1px solid var(--rule); }`.
11. **Reduced motion** (NFR): `@media (prefers-reduced-motion: reduce) { *, *::before, *::after { transition: none !important; } }`.
12. **Class names.** Add the class names listed under Affected files to `src/App.tsx` and
    `src/components/TaskList.tsx`. Do not change text, attributes or element order.
13. **Contrast helper.** Write `e2e/support/contrast.ts` with `parseRgb` (accepts `rgb()` and
    `rgba()`) and `contrastRatio`, using the WCAG 2.1 sRGB linearisation and `(L1 + 0.05) / (L2 + 0.05)`.
14. **Styling spec.** Write `e2e/styling.spec.ts` with the tests in the mapping below. Use
    role- and label-based locators where they exist, and the new class names only for elements
    without a role (description, metadata line). Read computed styles with
    `locator.evaluate(el => getComputedStyle(el).<prop>)`. Read the placeholder colour with
    `getComputedStyle(el, "::placeholder").color`. Compute the effective background by walking
    ancestors to the first non-transparent `background-color`. Each test starts with
    `page.goto("/")` in a fresh context, so the tests stay independent under `fullyParallel`.
15. **Run the checks**: `npm run lint`, `npm run typecheck`, `npm run test:unit`, `npm run build`
    and `npm run test:e2e` (using the run's `PORT`/`E2E_PORT`). Confirm with `git diff` that
    `src/App.test.tsx` and `e2e/app.spec.ts` are unchanged.

## Criterion-to-test mapping
All tests named below are in `e2e/styling.spec.ts` (Playwright, Chromium), inside
`test.describe("editorial styling (SDLC-17)")`, unless the row says otherwise.

| Criterion | Test (file and name) | Type |
|---|---|---|
| AC1 | "AC1 applies the bundled stylesheet with a paper background and ink text, loading nothing external". It asserts that `body` has a `background-color` that is not `rgb(255, 255, 255)` and equals the paper token, that `color` is not `rgb(0, 0, 0)` and equals the ink token, that `document.styleSheets.length > 0`, and that every network request's origin is the app's `baseURL` origin. | e2e |
| AC2 | "AC2 sets the masthead in a serif stack, larger than all other text, with a rule beneath". It asserts that the h1 `font-family`'s last generic is `serif`, that the h1 `font-size` is greater than the computed `font-size` of every other element with a text node in `main` (including controls and buttons), that the h1 sits inside the column and is centred, and that `border-bottom-width` ≥ 1px with a non-`none` `border-bottom-style`. | e2e |

It asserts that every `h2` has a `font-family` equal to the h1's, that `.task-description` has `font-size` ≥ 16px and a ratio of line-height to font-size between 1.4 and 1.7, and that its `font-family` ends with a generic family. | e2e |

| AC6 | "AC6 separates unbulleted tasks with thin rules and no card styling". ## Risks
| Risk | Mitigation |
|---|---|
| The TypeScript 6 side-effect import check rejects `import "./styles.css"` | Add `src/vite-env.d.ts` with `vite/client` types (step 1), then run `npm run typecheck` before writing any CSS |
| The CI Linux runner has none of the named serif fonts, so the page renders in the generic `serif` fallback | The stacks end in generic families (NFR Compatibility). The tests assert declared `font-family` and computed sizes, not rendered glyphs, and do no pixel comparison. Screenshots are for human review only |
| `text-transform: uppercase` changes `innerText` and could affect text-based locators | Only the labels and the metadata line are uppercased. Playwright `getByLabel`, `getByText` and `getByRole({ name })` match case-insensitively by default, and `toHaveText` uses `textContent`. AC13 requires the existing suites to pass unmodified, which is the check |
| Wrapping the controls in flex groups would break the SDLC-13 unit assertion that the controls share a parent | No wrapper elements are added. `flex-wrap` is applied to the existing `.controls` div |
| The controls row overflows at exactly 768px if the select or labels are wider than expected | Search uses `flex: 1 1 12rem; min-width: 0`. The AC7 test runs at exactly 768px to catch overflow. If it fails, reduce `gap` or the `flex-basis` of Search |
| `:focus-visible` does not match on programmatic focus | The AC9 test reaches controls with real `Tab` key presses, which Chromium treats as keyboard modality |
| Hover styles reduce contrast on the star button | Hover changes only the underline or a light tint, and AC10 measures the resting states. The implementer keeps any hover colours at ≥ 4.5:1 |
| Computed-style e2e tests are brittle if markup changes later | Tests use roles and labels first and the documented class names second. Each assertion tests a spec threshold, not an exact pixel value |

## Rollback implications
This is a presentation-only change. It adds no persisted state, storage format, migration or
dependency. Reverting the ticket's commit removes the stylesheet, the type reference, the class
names and the styling spec. The app returns to browser-default rendering with identical
behaviour, and existing localStorage data (starred tasks) is unaffected.
