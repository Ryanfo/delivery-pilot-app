# Release proposal

> Provenance (ticket, revision, accepted candidate SHA) is added by the coordinator.

## Release notes
**The task list has a new editorial look.** The page now reads like a page from a printed
publication:

- A large serif "Task list" masthead with a double rule beneath it.
- An off-white "paper" background with near-black "ink" text and one deep-red accent colour.
- All content sits in a single centred reading column (up to 48rem wide).
- Task titles use the masthead's serif face. Descriptions use a readable 16px body face.
- Control labels ("Status", "Starred only") and each task's status, priority and due-date line
  appear as small, uppercase, letter-spaced grey text.
- Thin rules separate the tasks. There are no cards or shadows.
- A starred task's button is filled with the accent colour. It still reads "★ Starred" or
  "☆ Star", so the state is never shown by colour alone.
- Every control shows a clearly visible 2px accent focus ring when you reach it by keyboard.
- The "No tasks match the current filter." message is shown in muted italic text.
- The controls fit on one row on wider screens and wrap neatly on phones down to 320px wide.

**Removed:** the "HELLO WORLD" welcome line under the heading (added by SDLC-7) is gone. The
controls now follow the masthead directly. The developer asked for this removal and an approver
accepted it (deviation D1, specification v002).

Behaviour is unchanged: filtering, starring, search, counts and saved starred tasks work
exactly as before. No new dependencies are added, and no external fonts or resources are
loaded. Text contrast meets WCAG 2.1 AA, and transitions are turned off when the user prefers
reduced motion.

## Smoke checks
Run these on the merged `main` commit in the local-pilot profile. Use a free port in place of
`$PORT`; do not assume the default.

1. `git checkout <merge commit on main> && npm ci`. The install completes with no errors.
2. `npm run lint && npm run typecheck && npm run test:unit`. All pass (44 unit tests at the
   candidate).
3. `npm run build`. It succeeds and `dist/assets/` contains one `index-*.css` (about 3 kB).
   `grep -rE "url\(|@import|https?://" dist/assets/*.css` finds no external references.
4. `npm run test:e2e` (with the run's port). All Playwright tests pass, including the
   `editorial styling (SDLC-17)` suite in `e2e/styling.spec.ts` and both tests in
   `e2e/app.spec.ts` (16 tests at the candidate).
5. `PORT=$PORT npm run preview` and open `http://127.0.0.1:$PORT/` in a desktop browser about
   1280px wide. Expect an off-white page, a large centred serif "Task list" masthead with a
   double rule under it, and content in a centred column with equal side margins. There is no
   "HELLO WORLD" text anywhere.
6. Check the task list. There are no bullets, thin rules sit between tasks, and there are no
   cards or shadows. Task titles are in serif. Each metadata line is small, uppercase and grey.
7. Click "☆ Star" on "Draft onboarding checklist". The button turns accent-filled with light
   text and reads "★ Starred". Reload the page. The task is still starred, which shows
   persistence is unaffected.
8. Press Tab repeatedly from the top of the page. The Status select, the Starred only checkbox,
   the Search field and each star button show a visible red 2px focus ring.
9. Type `zzz` into Search. The list is replaced by "No tasks match the current filter." in
   muted italic text. Clear the field. Type `review`. Exactly one task is shown.
10. Use the Status select and the Starred only checkbox. Filtering and the results count behave
    as before the release.
11. Narrow the window, or use device emulation, to 320px wide. There is no horizontal
    scrolling, the controls wrap with each label beside its control, Search takes a full row,
    and all text and buttons stay readable and usable.
12. Open the browser's network panel and reload. Every request goes to `127.0.0.1:$PORT`, with
    no font, CDN or other external requests.

## Rollback
This is a presentation-only change. It has no migrations, no storage format changes and no new
dependencies, so rolling back is a code revert only.

1. Identify the merge commit for SDLC-17 on `main` (the commit the coordinator recorded as the
   release).
2. Create a branch from the latest `main` and run `git revert -m 1 <merge-sha>`. If the PR was
   squash-merged, use `git revert <squash-sha>`.
3. Open a PR for the revert. When CI (lint, typecheck, unit, build, e2e) passes and a human has
   reviewed it, merge it.
4. On the reverted `main`, run `npm ci && npm run build && npm run test:unit && npm run test:e2e`.
   The page renders with browser defaults again.
5. Note that the revert also restores SDLC-7's "HELLO WORLD" welcome section and its original
   test assertions. Tell the product owner. If only the styling should go, remove the welcome
   section again in a follow-up ticket.
6. Users need no action. Starred tasks in localStorage are unaffected by the release and by
   the rollback.
7. Record the rollback and its reason on SDLC-17 in Jira.
